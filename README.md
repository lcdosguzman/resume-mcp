# resume-mcp

Go MCP server that exposes a candidate profile and resume format to an LLM,
then saves the tailored resume generated by the model as a Markdown file.

This is a basic MCP created to provide a simple structure for understanding
how these types of applications work: how tools are exposed to the model, how
job context is prepared, and how results are saved in Markdown format. It is
intended as an educational example rather than a production-ready solution.

The server does not generate resume content itself. The connected LLM is
responsible for analyzing the job description, writing the resume, and calling
the `save_resume` tool.

## LLM Setup Guide

When helping someone configure this project, follow this order:

1. Confirm the operating system, available shell, and Go version with
   `go version`. Go 1.22 or newer is required.
2. Work from the cloned project root, where `go.mod` and `cmd/resume-mcp/main.go` are located.
3. Verify that `data/profile.json` exists and contains real candidate data.
4. Run `go test ./...` and build with `go build -o resume-mcp-server ./cmd/resume-mcp`.
5. Start `./resume-mcp-server` in a separate terminal.
6. Check `http://127.0.0.1:8090/health` before configuring an MCP client.
7. Configure the client using the instructions below.
8. To generate a resume, provide the job description to the MCP workflow and
   verify that `save_resume` returns a download URL.

Do not invent profile data or report a successful setup without checking
`go version`, `go test ./...`, and `/health`. When troubleshooting, request the
exact command and its complete output first.

## Requirements

- Git, to clone the repository.
- Go 1.22 or newer (`go version`).
- Node.js and `npx` are required only when using the `mcp-remote` bridge.

The Go server has no external Go dependencies and does not require internet
access to build.

Generated binaries and resumes are local artifacts and are not tracked by Git.

## Download and Install

Clone the repository and move into its root directory:

```bash
git clone https://github.com/lcdosguzman/resume-mcp.git
cd resume-mcp
```

Verify the Go installation and run the tests before starting the server:

```bash
go version
go test ./...
```

## Configure Candidate Data

Edit these files before using the server:

- `data/profile.json`: real personal details, work experience, education, skills,
  certifications, and languages.
- `data/resume_format.json`: output sections, ordering, style, length, and
  fit-evaluation rules.

`data/profile.json` contains the candidate's personal and professional
information. Replace the example data with your own data before connecting an
LLM, and do not commit secrets or sensitive information.

The profile uses English JSON keys. Keep the structure consistent when adding
or removing fields. Do not place secrets in the profile. The generated resume
uses the predominant language found in the profile's narrative content: Spanish
when Spanish is the majority, or English when English is the majority.

## Build and Run

```bash
cd /path/to/resume-mcp
go test ./...
go build -o resume-mcp-server ./cmd/resume-mcp
./resume-mcp-server
```

For local development, you can run the server without creating a binary:

```bash
go run ./cmd/resume-mcp
```

The binary created by `go build` is only a local artifact. It is not required
to download or commit it to the repository.

The default MCP endpoint is `http://127.0.0.1:8090/mcp`. Change the port with
`MCP_PORT`:

```bash
MCP_PORT=9000 ./resume-mcp-server
```

If download links must use a hostname or address other than localhost, set
`MCP_PUBLIC_URL`:

```bash
MCP_PORT=9000 MCP_PUBLIC_URL=http://192.168.1.20:9000 ./resume-mcp-server
```

The server listens on `127.0.0.1` by default. Check its health with:

```bash
curl http://127.0.0.1:8090/health
```

## Manual MCP Test

List the available tools:

```bash
curl -s -X POST http://127.0.0.1:8090/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

Read the profile:

```bash
curl -s -X POST http://127.0.0.1:8090/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"get_profile","arguments":{}}}'
```

## MCP Tools

| Tool | Input | Purpose |
|---|---|---|
| `get_profile` | `{}` | Returns the complete `data/profile.json`. |
| `get_resume_format` | `{}` | Returns the resume output format. |
| `prepare_job_context` | `{ "job_description": "..." }` | Returns the profile, format, job description, and instructions for writing a tailored resume. |
| `save_resume` | `{ "content": "...markdown...", "file_name": "optional" }` | Saves the Markdown resume in `output/` and returns a download URL. |

**Client compatibility:** MCP clients must use the English tool names and
argument names listed above. The current public contract is
`get_profile`, `get_resume_format`, `prepare_job_context`, and `save_resume`,
with `job_description`, `content`, and `file_name` as applicable. Clients
configured with the previous Spanish names must be updated before use.

Typical LLM workflow:

1. Call `prepare_job_context` with the complete job description.
2. Write a tailored Markdown resume using only evidence from the profile.
3. Include an honest 1-10 fit score, strengths, and weaknesses or gaps.
4. Call `save_resume` with the final Markdown content.

## MCP Prompts

The server also exposes the `tailor_resume` prompt. It receives a job
description and an optional output file name, then guides the LLM through the
complete workflow: call `prepare_job_context`, write the tailored resume in
Markdown, and call `save_resume`.

List the available prompts:

```bash
curl -s -X POST http://127.0.0.1:8090/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":3,"method":"prompts/list"}'
```

Get the `tailor_resume` prompt:

```bash
curl -s -X POST http://127.0.0.1:8090/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":4,"method":"prompts/get","params":{"name":"tailor_resume","arguments":{"job_description":"We are looking for a Go backend developer with experience in REST APIs, Docker, and AWS.","file_name":"go_backend_resume"}}}'
```

The prompt does not include the profile or resume format itself. The LLM is
instructed to obtain that context through `prepare_job_context`, avoiding
duplication between prompts and tools.

Generated files are saved locally in `output/` with a timestamp suffix, for
example `resume_disney_20260820_120000.md`. They are served while the server is
running at `http://127.0.0.1:8090/downloads/<file>`. The `output/` contents are
ignored by Git; only `output/.gitkeep` is retained.

## Connect an MCP Client

This server uses simple Streamable HTTP: JSON-RPC 2.0 over POST at `/mcp`,
without server-sent event streaming.

### Claude Desktop or Claude Code

These clients commonly expect an stdio server. Use the `mcp-remote` bridge in
the client configuration, for example:

```json
{
  "mcpServers": {
    "resume-mcp": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://127.0.0.1:8090/mcp"]
    }
  }
}
```

Node.js must be installed, and the Go server must already be running. Restart
the MCP client after changing its configuration.

### MCP Inspector

```bash
npx @modelcontextprotocol/inspector
```

Point the inspector to `http://127.0.0.1:8090/mcp` as an HTTP MCP server.

## Troubleshooting

- **`go: command not found`:** install Go 1.22 or newer and reopen the shell.
- **`could not read data/profile.json`:** run the binary from the project root
  and verify that `data/profile.json` exists.
- **`bind: address already in use`:** choose another port with `MCP_PORT` and
  use the same port when checking health and configuring the MCP client:

  ```bash
  MCP_PORT=9000 ./resume-mcp-server
  curl http://127.0.0.1:9000/health
  ```
- **Download URL does not open:** make sure the server is still running and
  that the URL uses the configured port.
- **The client cannot find the tools:** verify `/health`, verify the `/mcp` URL,
  and restart the client after configuration changes.
