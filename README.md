# resume-mcp

Go MCP server that exposes a candidate profile and resume format to an LLM,
then saves the tailored resume generated by the model as a Markdown file.

This project is intended as an educational example to help developers understand
how Model Context Protocol (MCP) servers are built, how tools are exposed to the
model, how context is prepared, and how generated output is persisted for use in
real workflows.

The goal is not to build a complex production system, but to provide a clear and
reusable reference for building MCP-based tools in Go with a simple, readable
architecture.

The server does not generate resume content by itself. The connected LLM is
responsible for analyzing the job description, creating the tailored resume, and
calling the `save_resume` tool.

## Why this project exists

This project demonstrates a practical pattern:

- a client or agent calls a tool exposed by an MCP server
- the server returns structured context and instructions
- the model generates a tailored response based on that context
- the output is saved to disk for reuse or download

In this case, the use case is adapting a CV to a specific job description using
candidate profile data and a defined resume structure.

## How it works

The application follows a simple layered design:

1. Server layer
   - registers MCP tools and prompts
   - handles JSON-RPC requests
   - validates inputs and dispatches the request

2. Business layer
   - reads the candidate profile
   - reads the resume format
   - prepares the context for the LLM

3. Storage layer
   - saves generated resumes into `output/`
   - creates a download URL for each output file

4. Configuration layer
   - reads environment variables like port and public URL
   - validates runtime configuration before startup

## MCP tools

The server exposes these tools:

- `get_profile`
  - returns the complete candidate profile

- `get_resume_format`
  - returns the resume structure and required format

- `prepare_job_context`
  - prepares the full context for tailoring a CV to a job description

- `save_resume`
  - saves the generated Markdown resume and returns a download URL

## MCP prompts

The server also exposes the `tailor_resume` prompt, which guides the model through
this workflow:

1. read the job description
2. call `prepare_job_context`
3. write a tailored resume in Markdown
4. save it with `save_resume`

## Requirements

- Go 1.22 or newer
- Git
- Node.js and `npx` only if using the `mcp-remote` bridge

## Quick start

Clone the repository and enter the project folder:

```bash
git clone https://github.com/lcdosguzman/resume-mcp.git
cd resume-mcp
```

Check the Go installation and run the tests:

```bash
go version
go test ./...
```

Start the server:

```bash
go run ./cmd/resume-mcp
```

Check the health endpoint:

```bash
curl http://127.0.0.1:8090/health
```

The default MCP endpoint is:

```text
http://127.0.0.1:8090/mcp
```

## Configuration

You can override the default port and public URL with environment variables:

```bash
MCP_PORT=9000 go run ./cmd/resume-mcp
MCP_PORT=9000 MCP_PUBLIC_URL=http://127.0.0.1:9000 go run ./cmd/resume-mcp
```

## Candidate data and resume format

Before using the project with a real LLM, update these files:

- `data/profile.json`
- `data/resume_format.json`

The profile should contain real and useful candidate information without secrets or
sensitive data. The resume format defines the structure and sections the generated
CV should follow.

## Manual usage examples

List available tools:

```bash
curl -s -X POST http://127.0.0.1:8090/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

Read the profile:

```bash
curl -s -X POST http://127.0.0.1:8090/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"get_profile","arguments":{}}}'
```

## Why this is useful as a base project

This project is a practical example of how to build an MCP server in Go with:

- tools
- prompts
- input validation
- configuration handling
- file access
- LLM-driven workflow
- persistent output generation

It is a good starting point for learning the pattern without introducing excessive
complexity.

## Good practices already included

- clear separation of responsibilities by layer
- validation of required inputs and file paths
- safe file naming
- centralized configuration
- basic behavior tests

## Recommended improvements

If you want to take this repo one step further as a public reference, these are the
most valuable follow-ups:

- richer logging and observability
- more explicit validation and error messages
- better centralization of validation logic
- more integration tests around tool execution
- clearer documentation of the full MCP flow

## Final note

This repository is meant to be a clear, teachable example of how MCP works in a
real codebase. It is not intended to be a final production system, but rather a
solid, readable base that other developers can use to understand the pattern and
build on top of it.
